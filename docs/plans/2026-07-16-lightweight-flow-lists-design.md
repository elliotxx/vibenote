# Lightweight Flow Lists

## 目标

让用户在 Markdown block 中用纯文本列表快速表达并浏览完整流程，同时不引入 Mermaid 语法、独立画布或新的文件格式。

## 交互

- 连续的顶格箭头链或流程列表被识别为一个整体，而不是分别装饰每个词语。
- 顶层列表项显示为横向主流程，每个顶层 section 使用独立的阶段网格。
- 缩进列表显示为分支流程，并保留与主流程的层级关系。
- 以 `->` 开头的后续行显示为同一顶层逻辑下的另一条分支路径。
- 宽窗中每条路径保持水平方向，连接线固定为 30px，节点最长约 22 个字符后换行。
- 窄窗中路径转为纵向阅读；文本完整可见，不引入横向滚动、滚动提示或方向键滚动交互。
- section 只共享 root 列宽；每条路径在分支起点后独立紧凑排布，避免长节点扩大其他 lane 或 section 的空白。
- 节点内部可以换行，路径之间按纵向泳道排列，避免阅读顺序不明确。
- 节点只使用文字和连接线，不添加标签底色、圆角卡片或局部下划线。
- 流程视图显式使用所在 block 的奇偶背景与正文颜色；箭头不使用强调色，不增加独立面板底色或上下边框。
- 每个顶层流程 section 显示其源码在 block 内的行号；行号占用与 CodeMirror gutter 相同的宽度、背景和右边界，并与 root 行垂直居中。
- 主路径、分支竖干、折线和箭头共享同一个 SVG 坐标系、颜色、线宽、圆角端点和箭头 marker；主路径与分支主干真实相交。
- 节点前后间距固定为 8–12px，不使用节点最小宽度制造不可见空白。
- root 左内边距与普通 `.cm-line` 一致，确保 root 正文和相邻普通行左对齐；右侧保留约 14px 间距，root 与第一 lane 共用 3em 行高并垂直居中。
- 分支首节点与对应主路径 stage 共列；后续节点按各自路径内容宽度紧凑推进，节点之间保留 10px 文本间隙、30px connector 和 10px 箭头间隙。
- 流程视图处于当前 block 时为右上操作栏预留空间，窄窗下操作栏不遮挡顶部路径。
- 代码围栏、普通列表和不带空格的箭头保持原样；顶格的 `A -> B` 无需添加列表标记。
- 点击流程视图切回原始 Markdown 编辑；光标移出后恢复流程视图。
- 复制和保存始终使用原始 Markdown 文本。

## 实现

使用独立的 CodeMirror StateField、块级 replace widget 和 section 级共享坐标系：

- 从 Markdown block 中解析连续的顶格箭头链或流程列表组。
- 用一个块级 widget 替换整组源码，文字节点保留为 HTML。
- 每个 section 使用一个 SVG edge layer，内部由多个 path 和同一个 marker 绘制主路径、分支主干与 lane 连接线。
- SVG edge layer 固定在 section stage 上，并按节点的屏幕坐标绘制固定 30px 的横向连接线。
- 窄窗使用独立纵向拓扑：主路径沿内缩轨道纵向推进，分支从对应主节点阶段横向进入更深一级轨道；任何 edge 或 trunk 都不得与 stage 的 x=0 边界重合。
- 续行保留源文本的前导空白，按显示列寻找最近的父路径箭头列，得到 `attachStage`；若无法可靠匹配则按普通文本处理。
- 分支首节点与同阶段主路径节点共享横坐标，垂直主干挂在该阶段的连接线起点。
- 分叉处在前一节点后保留 10px 间隙和 20px 入射尾线，再由竖直 trunk 分出两条 30px 箭头；合并形态不得缺少入射尾线。
- 第一阶段直接分叉时，20px 入射尾线从 stage 起点进入 trunk，不能因为不存在前一 HTML 节点而省略。
- 窗口或节点尺寸变化后重新计算连接路径；连接线长度保持 28–32px，任意两条横向连接线长度差不超过 2px。
- 进入编辑状态时临时移除 widget，显示原始文本。
- replace widget 只替换最后一条流程源码行的内容，不吞掉其行尾换行，避免在下一 block 前留下额外的空白行。
- map 级 gutter underlay 连续覆盖整个流程高度的 gutter 内容区，行号本身透明叠放；保留 CodeMirror 原生 gutter 右边框，不再绘制第二条分界线或露出 section 间色带。
- 不修改编辑器文档，不增加运行时存储字段。

## 验证

- 连续流程只生成一个完整流程视图。
- 顶层逻辑、主路径和缩进分支保持正确层级。
- 水平、垂直和折线使用同一 SVG stroke 与 marker，主路径和分支连接处没有像素浅缝、悬空或粗细突变。
- 标准宽度与 360px viewport 均提供 DPR=1/2 证据；连接中心线像素扫描不出现明显浅于相邻 stroke 的 1px 列。
- 节点前后 gap 为 8–12px，短标签不额外产生超过 16px 的漂浮空白。
- 分叉入射尾线长度为 18–22px，并与 trunk 真实相交；无分支路径中每个 connector 起点距离前一节点 8–12px。
- 同一 block 内流程图背景与普通内容行一致，edge 颜色与节点正文颜色一致，上下边框宽度为 0。
- 顶层 section 行号与源码相对行号一致，右边缘和 gutter/content 分界误差不超过 1px，行号与 root 中心误差不超过 1px。
- 360px 下操作栏不遮挡路径，所有节点纵向排布且文本完整可见，无横向 overflow。
- 360px 下所有节点都在 map 边界内，长文本完成换行且不存在被裁切的残字；DPR=1/2 均保留证据。
- 标准宽度下 root/首节点中心差不超过 1px，最长 root 到首节点空隙为 48–64px，同 stage 节点跨 lane 左坐标差不超过 1px；360px 下 root 作为独立 section 标题置于纵向轨道上方。
- 真实笔记示例在 1100px / DPR2 与 360px 下均不产生横向 overflow，不显示滚动条或滚动提示。
- 每条横向连接线长度保持 28–32px，最长与最短之差不超过 2px；分支首节点与对应主路径节点横坐标误差不超过 1px。
- 360px 下所有 edge 的最小 x 坐标至少为 8px，分支轨道相对主轨道内缩至少 12px，分支 trunk 的起止点分别对应 stage 2 主节点和分支节点中心。
- 点击后可编辑原始 Markdown，移出后恢复流程视图。
- 代码围栏中的箭头不渲染。
- 自动保存后的内容与输入 fixture 完全一致。
